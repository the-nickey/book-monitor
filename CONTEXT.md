# book-monitor — контекст проекта

Монитор новых поступлений и продаж в антикварных книжных лавках → закрытый
Telegram-канал. Прод крутится 24/7 на VPS. Этот файл — полный контекст, чтобы
поднять/продолжить проект в любой сессии без опоры на память ассистента.

## Что делает

Четыре источника → один TG-канал, карточка на каждое новое событие:

| источник | что ловит | интервал |
|----------|-----------|----------|
| `abel` | полный каталог abelbooks: поступления, возвраты, продажи, цена/фото | 5 мин |
| `moscow`    | букинист moscowbooks.ru (фильтр год≥1940, за неделю) | 5 мин |
| `antique`   | новые поступления antiquebooks.ru | 1 час |

Формат карточки: `Источник – статус` + кликабельное название + цена. У проданных
дополнительно: `впервые заметили N дней назад – ДАТА` (+ «(в этот день стали
трекать историю)» для книг, замеченных только при первичном обстреле).

## Код (monitor.py — голый stdlib, zero-deps)

С 26.10.2026 Абель использует полный снимок каталога и `abel_state.json`.
ID больше не считается одноразовым событием: сохраняются статус, цена и ссылки
на фото каждого цикла, дата текущего поступления, история изменений и очередь
неотправленных уведомлений. Наблюдения и очередь пишутся атомарно до отправки;
неуспешная доставка повторяется после рестарта. Первый снимок при переходе тихий.
Фото для уведомления берётся из снимка конкретного события (из ссылки на превью
восстанавливается URL оригинала). Если снимок не содержит подходящей ссылки,
используется текущая галерея товара (`PICT`), затем `og:image` как запасной путь.
Это сохраняет фото нужного экземпляра при задержке доставки и не подставляет
устаревшую обложку из `og:image` вместо нового поступления.

`source_abel` обходит все страницы двумя работниками с паузами. Пустой ответ или
противоречивое наличие одного ID отменяют снимок; исчезновение ID само по себе
не объявляется продажей. Смена содержимого фото при неизменной ссылке отдельно
не определяется. Возврат и продажа целиком между обходами могут остаться незамеченными.

- Источники — функции `source_*()`, реестр `SOURCES = {имя: {fn, interval}}`.
  **Добавить сайт = одна функция + одна строка в SOURCES** (сначала разведать HTML/API).
- Детект новизны Moscow/Antique: множества ID в `state.json`. Абель использует
  историю в `abel_state.json`; старые множества `abel_new`/`abel_sold` сохраняются
  для совместимости, но не подавляют повторные циклы.
- Планировщик `run_loop`: каждый источник по своему интервалу + джиттер ±10%,
  базовый тик 15–25с. Интервал считается от начала обхода.
- **Прайс-база `books.csv`**: сайт обнуляет цену проданного → запоминаем цену, пока
  книга в наличии, подставляем при продаже + считаем days-on-shelf. Наполнение:
  проекция полного снимка Абеля каждые 5 минут. Колонки:
  id,title,price,first_seen,status,sold_date,days_on_shelf. История каждого цикла
  остаётся в `abel_state.json`, цена старого экземпляра не переносится на новый.
- Картинки: Telegram сам скачать не может (сайт отдаёт его UA заглушку) → качаем
  сами, шлём multipart-загрузкой (jpeg/png/webp); фолбэк — текст.
- Режимы: `--loop` (прод), `--dry [source]` (превью без отправки), `--test` (по 1
  карточке из каждого источника), `--snapshot` (обстрел прайс-базы + замер RAM).

## Ключевые находки (почему так)

- **abelbooks** — с 24.09.2026 на **Битриксе** (до этого WooCommerce Store API, теперь 404).
  HTML каталога `/kategoriya/?sort=new_desc&PAGEN_1=N`, 26 карточек на страницу, размер
  страницы не меняется. Карточка: `data-id`, `data-name`, `data-price` (рубли, у части
  проданных пусто/0), ссылка `/product/<slug>/`, превью 306px webp. Порядок: сначала
  все в наличии по убыванию id (новинки на 1-й странице), потом хвост «Нет в наличии»
  (бейдж `_not_avail`), тоже по id → проданные ловим diff-ом хвоста, идя с последней
  страницы назад (~50 стр, ~1.5 мин). Крупная обложка — `og:image` страницы товара (webp,
  Telegram принимает). Битрикс изредка отвечает 500 → `http_get` повторяет 5xx.
  Переезд: ID сменились, прайс-базу перенесли по нормализованному названию
  (2891 из 3099; разовый `migrate_bitrix.py`, бэкапы `*.woo-*` на сервере).
- **moscowbooks** — старый ASP, HTML-парсинг, id в `data-productid`, пагинация `&page=N`.
- **antiquebooks** — .php, HTML, UTF-8, id в `book=N`, цена `Цена: 200.000 руб.`.

## Деплой / апдейт

1. Правки `monitor.py` локально → `git commit && git push` (сначала `git pull --rebase`).
2. На сервере:
   ```
   cd /root/book-monitor
   systemctl stop book-monitor
   backup=/root/book-monitor-backup-$(date -u +%Y%m%dT%H%M%SZ)
   mkdir -m 700 "$backup"
   cp -a monitor.py state.json books.csv config.json "$backup"/
   [ ! -f abel_state.json ] || cp -a abel_state.json "$backup"/
   git fetch -q origin main && git merge --ff-only origin/main
   systemctl restart book-monitor
   ```
   (state.json tracked → сохраняем; books.csv/config.json untracked → reset их не трогает.)
- Подмена самой books.csv/abel_state.json: `systemctl stop` → scp файла → `systemctl start` (живая
  служба иначе перезапишет файл из BOOKS в памяти).

## Восстановление, если сервер умрёт

Для восстановления нужен свежий серверный бэкап: код + config.json + books.csv +
state.json + abel_state.json. Локальный перенос от 25.10 не содержит новой истории. Поднять
новый VPS (лучше **зарубежный** — Telegram без обходов; на РФ-VPS см. обход в DEPLOY.md),
скопировать папку целиком, поставить тот же systemd-юнит,
`systemctl start`. Продолжит с места — без пересева и без спама «старыми» новинками.

## Грабли сервера

- `/usr/bin/time` не установлен (минимальный Ubuntu) — RAM мерить внутренним `resource` (`--snapshot`).
- RuVDS периодически флапает DNS (`Errno -3 name resolution`) — `http_get` retry(2) + пропуск цикла ловят.
- Журнал systemd ~2 ГБ (потолок 10% диска), `journalctl` по нему на 436 МБ RAM читает
  минутами и грузит диск — брать `journalctl -u book-monitor -n 100`, без `--since`
  по всей истории. ~20 МБ/сутки в журнал пишет ssh-брутфорс (вход root по паролю открыт).
- На сервере живёт **второй, чужой** парсер `/root/book-monitors` (крон, `requests`+`bs4`,
  бот @Books_scrapper_bot, свои чаты). 03.10.2026 по просьбе починили и его: Абель
  переписан под Битрикс, мёртвый прокси (407) закомментирован в `.env`, кэш ссылок
  перенесён `/katalog/` → `/product/`; бэкапы `*.woo-20261003`, `.env.bak-20261003`.
  Сервер, судя по ключу `me@box` с 2024, не только наш.
